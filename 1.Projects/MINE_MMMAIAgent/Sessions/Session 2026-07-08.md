## Span status `UNSET` — implication diagnostic

Tous les spans sont `UNSET` (normal en OTEL pour un span non-planté). On ne sait pas encore si ADK stampe `ERROR` sur un échec — et le `no_answer` étant probablement une erreur amont **avalée**, le span coupable peut rester `UNSET`. → Diagnostic par **durée courte + waterfall tronqué + events exception + `lastChunk` backend**, **pas** par le status. À noter le jour où on capture un `no_answer` en live.

## GCS vs Sessions API — complémentaires

- **GCS `mmm-agent-chat-logs`** (écrit par `agent.ts`) : résumé de l'échange (question, réponse, `status`, `durationMs`, `requestId`, et surtout **`adkSessionId`**). Organisé par `client_id`.
- **Sessions API** (Agent Engine, clé = `adkSessionId`) : events internes (author par sous-agent, tool calls, SQL, réponses). **Rétroactif** et **gratuit** (session store managé).
- Le GCS logue déjà l'`adkSessionId` → **clé de jointure** vers la Sessions API.

## Root cause vérifiée — hallucination de tool

Un `no_answer` capturé en live (via l'alerte) et diagnostiqué : **`schema_agent` (Flash) a halluciné un appel `execute_sql`** — un tool réel du pipeline (`executor_agent`, `agent.py:370`) mais **absent de son toolset** (`schema_agent` n'a que `get_table_info`, `agent.py:244`). ADK renvoie **498** → le stream meurt → `no_answer` (catch-all `ChatbotError` côté front). **Non-déterministe** (hallucination LLM) → explique une seule alerte et pas de panne totale ; un re-run passe souvent.

**Suspect principal** : le `BUSINESS_CONTEXT` injecté dans l'instruction de `schema_agent` (`agent.py:242`) décrit le **pipeline SQL complet** → amorce l'agent « schéma-only » à tenter `execute_sql`.

**Fix candidats (à trancher)** :
1. **Scoper le `BUSINESS_CONTEXT` par agent** — retirer la partie exécution pour `schema_agent`. Compatible avec « enrichir pour la qualité » : c'est du **scoping**, pas de l'allègement global. *(Levier le plus propre.)*
2. Instruction explicite dans `schema_agent` : « `get_table_info` only, aucun autre outil ».
3. Retry backend unique sur 498 / stream vide (résilience ; coût = 1 invocation en plus).

> Supersede l'hypothèse « routage définitionnel » — mauvais diagnostic du même symptôme (« mort à `schema_agent` »).
