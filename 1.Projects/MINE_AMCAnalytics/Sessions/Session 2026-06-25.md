# Session — 25 juin 2026

Projet : [[AMC Analytics]]

## Ce qui a été fait

### Contexte

Deux besoins identifiés : (1) ajouter le module AMC Analytics au client Publicis (seulement 1 dashboard), (2) limiter L'Oréal aux 2 dashboards qui les concernent. Plutôt que de tout gérer en Firestore à la main, on a conçu un système de contrôle d'accès à deux niveaux.

---

### Système d'accès à deux niveaux

#### Niveau client — `availableDashboards`

Stocké dans `customers/{customerId}/products/amazon-marketing-cloud-analytics` → champ `availableDashboards: string[]`. Définit quels dashboards existent pour ce client.

- L'Oréal → `["audiences-insights", "mm-p2c"]`
- Publicis → `["etude-efficacite-video-amazon"]`

Configuration : via le nouvel onglet "Available Dashboards" dans la page Settings (visible admins plateforme uniquement), ou directement en Firestore.

#### Niveau utilisateur — `allowedDashboards`

Stocké dans `users/{userId}/products/amazon-marketing-cloud-analytics` → `access.allowedDashboards: string[]`. Définit, parmi les dashboards disponibles pour le client, lesquels chaque utilisateur peut voir.

Remplace l'ancien `access.dashboards: boolean`.

**Backward compat** : si l'ancienne valeur `dashboards: true` est présente et pas de `allowedDashboards`, le serveur renvoie tous les slugs disponibles (migration transparente).

---

### Endpoints ajoutés/modifiés

| Endpoint                      | Accès                       | Rôle                                                                                             |
| ----------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------ |
| `GET /settings/users`         | AMC admin                   | Retourne maintenant `{ users, availableDashboards }` au lieu de `AmcUser[]`                      |
| `PUT /settings/users/:userId` | AMC admin                   | Écrit `allowedDashboards: string[]` au lieu de `dashboards: boolean`                             |
| `GET /config`                 | Tous utilisateurs AMC       | Retourne `{ availableDashboards }` du client courant — fallback sur tous les slugs si doc absent |
| `PUT /settings/customer`      | Admin plateforme uniquement | Écrit `availableDashboards` dans le doc Firestore client                                         |

---

### Changements frontend

**Settings page (admin)** :

- Colonne "Dashboards" → liste de checkboxes par dashboard (au lieu d'un switch)
- Les checkboxes sont filtrées par `availableDashboards` du client — impossible de donner accès à un dashboard hors périmètre
- Nouvelle card "Available Dashboards" (visible admins plateforme) pour configurer le périmètre client sans aller dans Firestore

**Hub page** :

- `useAmcAccess` intersecte `allowedDashboards` (utilisateur) avec `availableDashboards` (client via `GET /config`)
- Si le config charge encore → fallback sur tous les slugs (pas de flash vide)

**DashboardPage** :

- Double garde : slug dans `allowedDashboards` **et** dans le registry — accès direct par URL impossible si non autorisé
