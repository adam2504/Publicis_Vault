## Obstacles résolus

| Erreur | Cause | Fix |
|---|---|---|
| 403 upload GCS | `GOOGLE_APPLICATION_CREDENTIALS` encore set → SA key utilisée au lieu de l'ADC perso | `os.environ.pop("GOOGLE_APPLICATION_CREDENTIALS", None)` avant `storage.Client()` |
| `RuntimeError` resource_name | `sync=False` → resource pas encore peuplée | Supprimer le `print(index.resource_name)` immédiat |
| 400 algorithmConfig missing | `create_tree_ah_index` sans paramètres Tree AH | Switch vers `create_brute_force_index` (mieux adapté pour 5595 vecteurs) |
| 403 index creation | SA Vertex AI interne sans accès GCS | `gcloud storage buckets add-iam-policy-binding` × 2 (`objectViewer` + `legacyBucketReader`) |
| 400 mauvaise région | Bucket `vertex-ai-agent-engine-staging` en `eu`, Vertex AI en `europe-west1` | Nouveau bucket `pmed-portal-feedgen-embeddings` en `europe-west1` |
| 400 sous-répertoires | Fichiers uploadés dans `en/` et `fr/` → non autorisé | Upload à plat : `embeddings_en.json` et `embeddings_fr.json` directement dans le préfixe |
| Vieux fichiers résiduels | Ancienne structure avec sous-dossiers encore présente dans le nouveau bucket | `gcloud storage rm -r` sur les sous-dossiers |

## Décisions prises

- Brute Force plutôt que Tree AH : 5595 vecteurs ne justifient pas l'index approximatif, brute force est exact et plus simple
- Bucket dédié `pmed-portal-feedgen-embeddings` en `europe-west1` plutôt que réutiliser un bucket existant (tous dans `eu` ou `europe-west9`)
- FAISS gardé en local pour les tests rapides, Vertex AI Vector Search pour la prod
